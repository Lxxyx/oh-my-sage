# 自动化图布局

MCP 与 Web 共用 Core 的 `layoutNodes`。创建规则和提交草稿时自动排版；更新时省略 `layout` 保留已有位置，传 `layout: {}` 明确重排。排版只修改 `cfg.pos`，不改变端口、连接、业务参数、变量作用域、备注内容或启用状态。直接调用 `layoutNodes` 必须 `await`。

## 从业务结构生成局部形状

`src/core/tools/layoutModel.ts` 识别局部结构，`layoutBranches.ts` 约束分支顺序，`layout.ts` 安排流程区块，`layoutQuality.ts` 按网关端口和曲线检查、改善连线。识别不依赖房间名、节点 ID、具体变量值或设备型号。

| 结构 | 识别条件 | 排列规则 |
| --- | --- | --- |
| 条件表 | 同一变量或设备属性沿失败端口继续判断 | 判断向下排列，命中后的独占动作链放在对应行右侧 |
| 模式行 | `modeSwitch` 的多个独占输出 | 每个模式一行，按输出端口顺序排列，串行动作向右展开 |
| 检查列 | 成功端口串联的多个判断 | 从上到下逐项检查；共享状态输入仍保留 |
| 动作列 | 一个端口并行触发多个独占的终端设备动作 | 按 `outputs` 数组顺序纵向排列，不受节点数组顺序影响 |
| 重试单元 | 循环触发计数器，计数器停止该循环 | 循环和计数器上下相邻 |
| 确认步骤 | 写入设备属性、延时、查询确认相同属性与值 | 三张卡片组成一列 |
| 定时退出 | 状态持续计时、状态检查、设备动作反馈停止或复位 | 组成右边界对齐的一列，让向上返回的控制线留在卡片外侧 |

局部形状是布局的原子单位，不因行宽而拆开。动作尾链遇到共享汇合点或外部触发点就停止吸收。不能可靠识别的结构退回普通节点，交给 ELK 分层。`direction: "DOWN"` 使用普通纵向分层，不套用面向左右端口的局部形状。

## 整体排列规则

1. 主线优先。区分执行边、状态边和停止／清零／复位边。主线已有路径时，反馈不重复决定层级；初始化同时连接复位端口时，也不通过反向约束制造新的排序环。只有控制关联的节点仍用布局关系保持邻近。
2. 一个流程一个区块，上下排列并留出间隔。`cfg.layoutGroup` 明确指定区块；未分组的连通流程各自成区。孤立卡片集中在独立区块内装箱，不填入其他流程之间。`cfg.layoutOrder` 提供区块顺序提示。
3. 分支按端口顺序排列。`met`／`output` 的独占下游位于 `unmet`／`output2` 的独占下游上方；多模式按输出端口次序排列。遇到共享汇合点或回到分叉节点就停止归属传播。区块提示顺序与分支冲突时，分支优先；不能形成一致顺序的循环保持稳定次序。后续避让不得交换分支。
4. 备注绑定流程。带 `layoutGroup` 的备注放在对应区块左侧，整块移动时一起移动；有显式分区备注时，未分组备注是整图说明，放在上方。没有显式备注分组时，使用原坐标的空间邻近关系推断归属，优先保持同一行的关联；处于所有流程上方的说明仍为总览。为了避开跨区长线，备注可以在所属区块的左侧上下移动。正文不变，尺寸尊重保存值或显式测量。
5. 默认保留完整流程；宽度超过 12000 时才尝试以 6000 为期望宽度折行。显式 `maxRowWidth` 同样是偏好，只允许在单条执行边连接的完整局部结构之间折行。多分支、共享条件、反馈环和宽条件表允许超宽。
6. 依据真实端口位置估算网关前向曲线与返回线。先避免穿过其他卡片及备注，再减少线与线相交、线长和画布面积。搜索仅移动完整局部形状或区块，不改变业务连接；可以调整区间留白，让返回线的水平段通过空白。对相互阻挡的形状执行有上限的双块尝试。超过 100 个节点或 180 条边时跳过这部分搜索，保留基础排版。
7. 固定随机种子、保留端口数组顺序；相同输入重复排版得到相同坐标。全部坐标计算并检查无重叠后才写回，失败不会留下半张已修改的图。

## 卡片尺寸

优先使用 `layout.nodeSizes` 提供的页面实测尺寸。`cfg.simplified: true` 的卡片保留已存实际尺寸；没有尺寸时使用保守估计。普通模式按节点类型、端口数量和动作参数估计尺寸，并保留更大的历史尺寸。已知旧算法的通用占位尺寸会恢复成对应类型的紧凑尺寸。

估计包含设备事件与属性、带参数动作、变量运算、逻辑节点和备注。尺寸随固件、字体及内容变化，不能把估计当作所有页面的精确测量；不会为了缩小画布而修改用户的简洁模式设置。

## 调用方式

`mijia_create_graph`、`mijia_graph_draft_begin` 和 `mijia_update_graph` 支持可选 `layout`：

```json
{
  "layout": {
    "direction": "RIGHT",
    "maxRowWidth": 6000,
    "nodeSizes": {
      "query1": { "width": 740, "height": 164 }
    }
  }
}
```

仅更新排版可传 `id` 和 `layout: {}`，启用状态沿用原规则。默认更新不移动旧卡片，为新增卡片寻找不重叠的空位。`layoutNodes` 返回包含区块范围、业务节点 `nodeIds`、对应备注 `noteIds` 和重叠检查结果的 `LayoutReport`。区块范围包含备注和预留空间。

## 验证与边界

`tests/core/layout.test.ts` 使用合成结构验证行列对齐、动作顺序、成功／失败分支、跨区排序、备注归属、共享汇合点、循环与复位、简洁模式、区间留白、孤立卡片装箱、端口曲线穿卡、长链折行、重复排版、异常时原子性和业务数据不变。离线调用布局算法无需连接网关。

真实规则应先读取最新图，只在停用实验副本上试排；完整图依次通过能力校验和结构校验后再写入，并回读确认坐标、业务数据和停用状态。过程数据可保留在会话中，无需生成本地规则快照或审计文件。

网关按 `cfg.pos` 显示卡片，但会按自身实现重算尺寸，并从左右端口绘制连线。ELK 的路由拐点不会写回网关，因此卡片无重叠不等于连线零交叉。端口及曲线模型来自页面测量，是避让依据，不是零交叉保证。复杂共享状态、反馈回路以及固件差异仍需在实际页面观察；只读坐标预览不能替代真实页面验证。应同时核对实际卡片尺寸、SVG 连线、备注正文是否溢出，以及分支在放大视图中的阅读顺序。

页面可能缓存编辑标签。外部更新后应关闭网页中的编辑标签再重新打开，避免用缓存页面保存覆盖新布局。源码构建后，已运行的 MCP 进程需要重新启动才会加载新算法和参数说明。
