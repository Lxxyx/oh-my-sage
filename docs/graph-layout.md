# 自动化图布局

创建规则和草稿提交都在 Core 的 `createGraph` 中自动排版。MCP 与 Web 共用 `src/core/tools/layout.ts`，使用 [ELK layered](https://github.com/kieler/elkjs) 处理分层、分支顺序和环路。`layoutNodes` 现在返回 Promise，直接调用者须 `await`。

## 默认行为

- 同一行从左向右推进；长流程按完整层折到下一行，默认行宽 3600。分支不会拆到不同的行。
- 无关联的连通分量从上往下分区。业务子流程互有关联时，可在节点 `cfg.layoutGroup` 中显式写相同分区名，用数值 `cfg.layoutOrder` 排列分区。
- 总览 `nop` 备注放在图上方；带 `layoutGroup` 的备注放在相应分区上方。保留备注原有尺寸与内容。
- 设备查询、事件、变量运算等采用不同的尺寸估计，不再统一使用 528×164。显式提供更大尺寸时不会缩小；动态卡片可传入页面实测尺寸。
- 停止、清零和状态复位连线不决定主流程层级，避免循环的下游被挤回第一列。网关的原始 `outputs` 完整保留。
- 默认更新保留已有卡片位置，新增卡片避让已有卡片。显式要求重新排版时才移动全图。

## 调用方式

`mijia_create_graph`、`mijia_graph_draft_begin` 和 `mijia_update_graph` 均支持可选 `layout`：

```json
{
  "layout": {
    "direction": "RIGHT",
    "maxRowWidth": 3600,
    "nodeSizes": {
      "query1": { "width": 740, "height": 164 }
    }
  }
}
```

`direction: "DOWN"` 使用纵向分层，此时不折行。更新时省略 `layout` 保留原坐标，传 `layout: {}` 重新排版。仅更新排版可以只传 `id` 和 `layout`；启用状态沿用原规则。

节点分区示例：

```json
{ "cfg": { "layoutGroup": "启动与确认", "layoutOrder": 1 } }
```

分区是呈现信息，不改变业务执行。变量依赖不一定通过边表达，因此算法不会凭节点 ID 猜测业务名称；AI 创建复杂规则时应根据设计表明确标注业务分区，并按需加入 `nop` 标题。

## 真实页面验证与边界

网关根据 `cfg.pos` 显示卡片，随后按节点类型自行重算卡片尺寸；它也根据左右端口自行画贝塞尔线或回绕线。ELK 的折线拐点没有写回到网关，不能承诺任意复杂图都没有线交叉。尤其是共享状态、复位及跨分区长线。

验证布局时先复制规则并保持关闭，复制本规则变量作用域；仅通过已安装的 Oh My Sage MCP 写入副本。能力校验、结构校验通过后再写入并回读，最后在真实网页检查：

1. 卡片边界不重叠，备注不遮挡业务卡。
2. 节点顺序、分区、折行方向可读。
3. 连线交叉和穿卡数量与原图比较。
4. 原图节点、配置与更新时间未变；副本仍关闭。

页面会缓存打开的编辑标签。外部 MCP 更新后，要关闭网页内的编辑标签再从列表重新打开，不能只切换路由；也不要用缓存页面的“保存”覆盖新布局。

本次用 40 个业务节点、52 条连线的关闭副本验证：卡片重叠从 6 对降为 0；独立端口间的连线交叉采样从 139 对降到 55 对；穿过其他卡片的连线从 32 条降到 15 条。新增了 5 个备注标题，业务端口与连线未改变。数字反映该样本和该固件页面，不是通用零交叉保证。

纯布局只需 `tsx` 离线调用 `layoutNodes`，无需任何网关连接。源码构建后，已运行的 MCP 进程必须重启才会加载新代码和工具参数。
